# INFINEX 冊子

大会パンフレット・プログラムを作るための Web アプリです。INFINEX 大会速報のバックアップから要項・組合せ・試合日程・トーナメント表・スポンサーを組み立て、各チームから集めたチーム紹介シート（Excel）で選手名簿を加え、印刷入稿用の PDF（塗り足し・トンボ付き）を書き出します。

冊子のデータはクラウド（Cloudflare）に保存されます。スマホとパソコンのどちらからでも、同じ冊子を開いて続きを編集できます。

## できること

- **クラウド保存**
  - 編集すると自動で保存（画面上部に「保存済み」「保存中」などを表示）
  - 冊子一覧から開く・複製・削除
  - 別の端末で更新された内容は、画面に戻ったときや45秒ごとの確認で自動で読み込む
  - 2つの端末で同時に編集して内容がぶつかったときは、上書きせずに、どちらを残すか確認する
  - 電波が切れても、編集内容は端末に一時保存し、つながったら自動で保存する
- **INFINEX 大会速報との連携**：バックアップ（`infinex-backup` 形式）から、大会情報、要項（本文・画像・自動項目）、チームとロゴ、組分け、日ごと・コートごとの試合日程、トーナメント表、スポンサーを取り込む。もう一度取り込むと、大会速報から作った章だけを置き換える
- **チーム紹介**：チーム紹介シート（Excel）の一括取り込み、配布用の空シートの書き出し、ロゴ・写真の一括登録
- **冊子の構成**：章立て、目次とページ番号の自動作成、ページ上限（100ページ）と中綴じ（4の倍数）の確認
- **デザイン**：「公式（厳格）」「プロフェッショナル」と、色・書体・余白を変えたカスタムパターン。表紙・裏表紙・広告ページには、別途デザインした画像や PDF（1ページ目）を全面配置
- **書き出し**：PDF（200／300／350dpi、塗り足し 3mm、トンボ）、画像も含めた1ファイルのバックアップ

## しくみ

フォルダを使わず、すべてのファイルを同じ場所に置く構成です。GitHub へは、ファイルをまとめて選んでドラッグするだけでアップロードできます。

| ファイル | 役割 |
|---|---|
| `index.html` | アプリの画面 |
| `worker.js` | API（Cloudflare Worker）。`/api/` だけを処理する |
| `schema.sql` | D1 のテーブル定義（最初に1回だけコンソールで実行） |
| `wrangler.jsonc` | Cloudflare の設定 |
| `.assetsignore` | 外から見えないようにするファイルの一覧（`worker.js`、`wrangler.jsonc`、`schema.sql`、`README.md` など） |
| `_headers` | セキュリティの設定 |
| `*.min.js` | ライブラリ（Excel読込・PDF作成・PDF読込）。版を固定して同梱 |
| `favicon.ico`、`*.png`、`infinex-logo.jpg`、`manifest.webmanifest` | INFINEX のアイコン |

| 保存するもの | 保存先 | 理由 |
|---|---|---|
| 冊子の文章・構成・チーム名簿（1冊あたり数十〜数百KB） | D1（データベース） | 版の管理ができ、同時編集の確認に使える |
| ロゴ・写真・表紙などの画像 | Workers KV | 画像は大きく、D1 の1行の上限（2MB）を超えるため。内容の SHA-256 を名前にし、同じ画像は1回だけ保存する |

## 公開の手順（GitHub と Cloudflare）

大会速報と同じ流れです。大会速報より、画像の保存場所（KV）を作るステップが1つ多くなっています。

### ステップ1：GitHub にアップロードする

1. GitHub で新しいリポジトリを作ります。名前は `infinex-booklet` にしてください。「Add a README file」などのチェックは付けません。
2. 作成後の画面にある「**uploading an existing file**」をクリックします。
3. zip を右クリックして「すべて展開」を選びます。展開してできたフォルダを開くと、21個のファイルが並んでいます（フォルダはありません）。
4. `Ctrl + A` で**21個すべて**を選び、ブラウザの画面にドラッグ＆ドロップします（「choose your files」から選んでも構いません）。
5. 一覧に `.assetsignore` が含まれていることを確認して、「**Commit changes**」を押します。
   - `.assetsignore` は、`worker.js` や設定ファイルを外から見えないようにするためのファイルです。
6. リポジトリのトップに、`index.html`、`worker.js`、`wrangler.jsonc`、`schema.sql`、`.assetsignore` などが並んでいれば成功です。

### ステップ2：データベース（D1）を作る

1. [dash.cloudflare.com](https://dash.cloudflare.com/) にログインし、「ストレージとデータベース（Storage & Databases）」→「D1 SQL データベース」→「作成（Create）」を選びます。
2. 名前に `infinex-booklet-db` と入力して作成します。
3. 作成後の画面に表示される **データベースID** をコピーし、メモ帳などに貼っておきます。
4. 同じ画面の「**コンソール（Console）**」タブを開きます。
5. 別のタブで GitHub のリポジトリを開き、`schema.sql` を開きます。右上のコピーボタンで中身をすべてコピーします。
6. Cloudflare のコンソールに貼り付けて「実行（Execute）」を押します。
7. 「テーブル（Tables）」タブに `projects`、`assets`、`asset_refs`、`login_attempts` が並べば完了です。

### ステップ3：画像の保存場所（KV）を作る

1. 「ストレージとデータベース（Storage & Databases）」→「Workers KV」→「作成（Create instance）」を選びます。
2. 名前に `infinex-booklet-files` と入力して作成します。
3. 一覧に表示される **ID**（32文字の英数字）をコピーし、メモ帳などに貼っておきます。

### ステップ4：ID を登録する

1. GitHub のリポジトリで `wrangler.jsonc` を開き、右上の鉛筆マーク（Edit this file）を押します。
2. 次の2か所を、メモしておいた ID に置き換えます。前後の `"` は消さないでください。
   - `REPLACE_WITH_YOUR_D1_DATABASE_ID` → ステップ2のデータベースID
   - `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` → ステップ3の KV の ID
3. 「**Commit changes...**」→「Commit changes」を押して保存します。

### ステップ5：Cloudflare で公開する

1. 「Workers & Pages」→「作成（Create）」→「リポジトリをインポート（Import a repository）」を選び、`infinex-booklet` を選びます。一覧に無い場合は、GitHub の連携設定でこのリポジトリへのアクセスを追加してください。
2. 設定画面で次のように入力します。
   - **プロジェクト名**：`infinex-booklet`（`wrangler.jsonc` の `name` と同じにします）
   - **ビルドコマンド**：空欄
   - **デプロイコマンド**：`npx -y wrangler@4 deploy`
   - **ルートディレクトリ**：空欄または `/`
3. 「デプロイ」を押します。数分で「成功（Success）」になります。

### ステップ6：パスワードを登録する

1. 作成された Worker（`infinex-booklet`）を開き、「設定（Settings）」→「変数とシークレット（Variables and Secrets）」に進みます。
2. 「追加（Add）」を押し、**種類（Type）を「シークレット（Secret）」**にして、次の2つを登録します。
   - `ADMIN_PASSWORD`：冊子アプリのログインパスワード。冊子を編集する人で共有します。推測されにくいものにしてください。
   - `SESSION_SECRET`：英数字を**40文字以上でたらめに**並べたもの。パスワード管理アプリの自動生成機能を使うのが確実です。
3. 「デプロイ（Deploy）」または「保存（Save）」を押します。

### ステップ7：動作を確認する

1. Worker の画面に表示されている `https://infinex-booklet.<アカウント名>.workers.dev` を開きます。
2. ステップ6のパスワードと、あなたの名前（例：「山田（PC）」）を入れてログインします。名前は、冊子一覧や同時編集の確認で「誰が更新したか」として表示されます。
3. 「大会速報のバックアップから作る」で冊子を作り、画面上部が「保存済み」になることを確認します。
4. スマホで同じアドレスを開いてログインし、冊子一覧に同じ冊子が出れば完了です。スマホでは、共有メニューの「ホーム画面に追加」で INFINEX のアイコンから開けるようになります。

ステップ5の直後、ステップ6の前に開くと「初期設定が完了していません」と表示されますが、パスワードを登録すれば解消します。

## 更新のしかた

GitHub のリポジトリで「Add file」→「Upload files」から変更したファイルをアップロードして「Commit changes」を押すと、Cloudflare が自動で公開し直します。冊子のデータ（D1・KV）は更新の影響を受けません。

## 費用（無料プランの範囲）

| 項目 | 無料プランの上限 | この冊子アプリでの目安 |
|---|---|---|
| 画面の配信（静的ファイル） | 無制限 | — |
| Worker（/api/ の処理） | 1日 10万回 | 1人が1日編集して数百〜千回程度 |
| D1 の保存容量 | 5GB | 冊子1冊あたり 数十〜数百KB |
| KV の保存容量 | 1GB | 冊子1冊あたり、ロゴ64点で 3〜6MB、チーム写真も載せると 20〜40MB |
| KV の書き込み | 1日 1,000回 | 画像1点につき1回。同じ画像は再送しない |

チーム写真を多く載せる冊子を年間に何十冊も作る場合は、KV の 1GB が先に上限に近づきます。その場合は、画像の保存先を R2（無料枠 10GB）に切り替えられます。使っていない画像は、冊子を開いたときに自動で整理されます（1日以上前に登録され、冊子で使われていない画像）。

## 使うときの注意

- **ログインの範囲**：ログインはパスワード1つの共有方式です。パスワードを知っている人は、すべての冊子を見て編集できます。
- **同時編集の確認**：「この端末の内容で上書き」を選ぶと、もう一方の端末の変更は失われます。迷ったときは、確認画面の「この端末の内容をファイルに保存」で控えを残してから選んでください。
- **ログインの有効期間**：30日です。期限が切れても、編集中の内容は端末に残り、もう一度ログインすると保存されます。
- **PDF の文字**：PDF はページを高解像度の画像にして作ります。文字を選択できる PDF が必要な場合は、「PDF書き出し」→「ブラウザで印刷」から PDF に保存してください。
- **色の形式**：色は RGB で書き出します。印刷所から CMYK を指定された場合は、デザイン会社や印刷所で変換してもらってください。

## 手元で動かす（開発者向け）

Node.js 20 以上が必要です。同じフォルダで次を実行し、http://127.0.0.1:8787 を開きます。

```bash
# .dev.vars を作り、ADMIN_PASSWORD と SESSION_SECRET（40文字以上）を書く
npx -y wrangler@4 d1 execute infinex-booklet-db --local --file=schema.sql
npx -y wrangler@4 dev
```
